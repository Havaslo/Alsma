# MAX-бот

Backend принимает события MAX на `POST /api/max/webhook` и отправляет ответы через `https://platform-api2.max.ru/messages`. Текст передаётся в тот же `AiAgentService`, что используется сайтом, поэтому применяются общие база знаний, сценарии, правила передачи и проверка наличия.

## Переменные

Настройте серверные переменные в Environment/Integrations:

- `MAX_BOT_TOKEN` — токен MAX-бота, только backend;
- `MAX_BOT_WEBHOOK_SECRET` — секрет длиной не менее 16 символов для проверки входящих webhook-запросов;
- `MAX_BOT_WEBHOOK_URL` — публичный URL окружения для регистрации webhook, например `https://<backend>/api/max/webhook`.

Для preview и production значения URL и секрета должны быть отдельными. Один и тот же MAX-токен может иметь ограничения платформы на одновременную регистрацию нескольких webhook-подписок; если MAX разрешает только одну активную подписку, используйте отдельного бота/токен для параллельного preview.

MAX должен передавать секрет в заголовке `X-Max-Webhook-Secret` или `X-Max-Bot-Secret-Token`. Запросы без секрета отклоняются, если `MAX_BOT_WEBHOOK_SECRET` настроен.

## Поведение

События, отличные от `message_created`, подтверждаются без запуска агента. Текстовые сообщения сохраняются в общей истории обращений, а отдельный MAX-чат получает стабильный conversation ID, поэтому контекст диалога сохраняется между webhook-вызовами. Ответ агента отправляется как обычное текстовое сообщение MAX.

Проверка готовности: `GET /api/max/readiness` возвращает только статус конфигурации и не раскрывает токен.

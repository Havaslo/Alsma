# MAX-бот

MAX-бот использует тот же `AiAgentService`, что и сайт. Поэтому ответы берут опубликованную базу знаний, сценарии и правила передачи из админ-панели, используют актуальное наличие Eptera и формируют публичные ссылки на страницы сайта и подборку бронирования.

## Конфигурация

Серверу необходимы следующие переменные из Environment / Integrations:

- `MAX_BOT_TOKEN` — токен бота, используется только backend и передаётся в `Authorization` без `Bearer`;
- `MAX_WEBHOOK_SECRET` — секрет webhook;
- `MAX_BOT_WEBHOOK_URL` — публичный HTTPS-адрес backend; callback строится как `/api/max/webhook`;
- `MAX_BOT_SITE_URL` — публичный адрес frontend для ссылок в сообщениях.

При старте backend проверяет токен через `GET /me` и регистрирует подписку `message_created` через `POST /subscriptions` с callback и секретом. MAX должен передавать тот же секрет в заголовке `X-Max-Bot-Api-Secret`. Вебхук отвечает `200` до обработки события; повторы событий с одинаковым идентификатором не запускают агента второй раз.

## Диалог и менеджер

Для каждого MAX-чата создаётся стабильное обращение. После сообщения гостя агент отвечает через MAX и сохраняет общий с сайтом контекст. При действии `transfer` обращение переключается в режим менеджера: новые сообщения гостя больше не идут AI, а сообщения менеджера из существующей карточки обращения автоматически доставляются в тот же MAX-чат. Возврат обращения в режим AI продолжает тот же контекст.

MAX принимает получателя только в query-параметре `chat_id` запроса `POST /messages`; тело запроса содержит текст и вложения. Сервис отправки валидирует идентификатор чата и длину текста, а временные ошибки MAX повторяются ограниченно без вывода текста сообщений или секретов в журнал.

Проверка без раскрытия секретов: `GET /api/max/readiness` сообщает наличие токена, секретов и URL. При ошибке регистрации подписки backend остаётся работоспособным и записывает только безопасное описание ошибки.

# Голосовой агент через Mango Office

## Цепочка звонка

`Mango Office` → входящий webhook/медиаканал Mango → backend голосового агента →
Mango API для перевода на номер менеджера.

Внешние телефонные станции и промежуточные голосовые шлюзы в проекте не
используются.

## Backend-контур

- `POST /api/voice-agent/mango/webhook` принимает события Mango идемпотентно по
  `callId`.
- `POST /api/voice-agent/answer` формирует ответ агента по базе знаний.
- `POST /api/voice-agent/tools` выполняет `knowledge_answer`,
  `create_booking_request` и `transfer_to_manager`.
- Перевод выполняется официальной командой Mango `blind` на
  `T2_TRANSFER_NUMBER`.
- Завершение события сохраняет транскрипцию, итог, извлечённые данные и запись,
  если Mango передал доступную HTTPS-ссылку.

## Переменные

- `MANGO_VPBX_API_KEY` и `MANGO_VPBX_API_SALT` — подпись запросов Mango.
- `T2_TRANSFER_NUMBER` — номер менеджера или очереди.
- `VOICE_AGENT_PUBLIC_WEBHOOK_URL` — публичный URL webhook Mango.
- `AMAZI_AI_GATEWAY_OPENAI_API_KEY` и
  `AMAZI_AI_GATEWAY_OPENAI_BASE_URL` — серверный доступ голосового агента к AI.

Секреты хранятся только на backend и не выводятся в логи или frontend.

## Логика агента

Агент отвечает по опубликованной базе знаний и активным правилам канала
`voice`, создаёт заявку при согласии клиента и немедленно выполняет перевод,
если клиент просит менеджера или вопрос нельзя безопасно решить автоматически.

## Записи и доступ

Звонки, транскрипции и записи доступны только администраторам и менеджерам с
соответствующим административным разрешением. Аудиозаписи удаляются из
управляемого хранилища, а карточки звонков — из базы данных через 30 дней.

## Требование к Mango

Для полноценного живого разговора Mango должен передавать в webhook или
медиаканал двустороннее аудио и события речи. Один только webhook с финальной
транскрипцией позволяет сохранить звонок, обработать заявку и выполнить
перевод, но не является живым аудиодиалогом. В проекте не добавляются
неподтверждённые Mango API-методы: используются только доступные события,
официальный API перевода и переданные Mango данные записи.

## Текущий статус SIP

Для временного прямого подключения OpenAI SIP используются
`OPENAI_SIP_API_KEY`, `OPENAI_SIP_BASE_URL` и `OPENAI_SIP_WEBHOOK_SECRET`.
OpenAI отправляет `realtime.call.incoming` на
`POST /api/voice-agent/sip/incoming`; backend проверяет подпись и принимает
звонок через Calls API с моделью `gpt-realtime`.

Диагностика доступна на `GET /api/voice-agent/sip/status`. SIP URI для Mango:
`sip:<OPENAI_PROJECT_ID>@sip.api.openai.com;transport=tls`. Обычные HTTP-запросы
и внутренний WebSocket-тест продолжают работать через Amazi AI Gateway.

# Голосовой AI-агент: Mango → SBC → OpenAI Realtime SIP

## Целевая маршрутизация

`публичный номер клиента (без изменений)` → безусловная переадресация мобильного оператора → `MANGO OFFICE` → внешний SIP/SBC (если Mango не может напрямую работать с требуемыми TLS/SRTP/кодеками) → `OpenAI Realtime SIP` → голосовой агент ALSMA.

При запросе человека агент инициирует перевод на менеджера через согласованный механизм Т2 (SIP REFER/attended transfer либо серверная переадресация на номер менеджера).

Публичный номер не переносится и не меняется. На этапе пилота рекомендуется отдельное тестовое окно/номер или ограниченное время переадресации.

## Что уже есть в проекте

- `VoiceCall` в PostgreSQL: идентификатор звонка провайдера, номер клиента, статус, транскрипт, запись, итог и извлечённые сущности.
- HTTP-контур `/api/voice-agent/*` для создания звонка, добавления сегментов транскрипта, ответа и завершения звонка.
- Общие опубликованные статьи базы знаний и активные правила с каналом `voice`.
- Общая доменная логика чат-агента и Eptera для актуального наличия; внутреннее название сервиса не должно звучать пользователю.
- Сценарии и правила передачи из админки как источник управляемой логики.

## Что добавлено в конфигурационный контур

Переменные должны задаваться только через Environment/Integrations и никогда не попадать во frontend или логи:

- `MANGO_API_BASE_URL`, `MANGO_API_KEY`, `MANGO_API_SECRET` — API и подпись событий MANGO OFFICE.
- `MANGO_SIP_TRUNK_URI` — адрес SIP-стыка Mango/SBC, если используется.
- `SBC_PUBLIC_BASE_URL`, `SBC_WEBHOOK_SECRET` — внешний медиашлюз и проверка его webhook.
- `OPENAI_REALTIME_SIP_BASE_URL`, `OPENAI_REALTIME_SIP_API_KEY`, `OPENAI_REALTIME_SIP_PROJECT_ID` — параметры Realtime SIP, если они выдаются используемым аккаунтом OpenAI.
- `T2_TRANSFER_NUMBER` — номер менеджера/очереди Т2; хранится только на backend.
- `VOICE_AGENT_PUBLIC_WEBHOOK_URL` — публичный HTTPS URL для событий Mango/SBC.

Наличие этих переменных проверяется без раскрытия значений через backend readiness endpoint.

## Что нужно запросить у клиента/провайдеров

### Mango

1. Номер Mango и способ входящей маршрутизации.
2. Доступ к API, ключ/секрет подписи и webhook-события.
3. Поддержку SIP-транка или media-streaming с двусторонним аудио.
4. Кодеки (предпочтительно G.711 µ-law/A-law), DTMF, TLS/SRTP, IP allowlist и лимиты параллельных линий.
5. Механизм перевода: SIP REFER, blind/attended transfer или API transfer.
6. Тестовый номер/режим и требования к записи разговоров.

### OpenAI Realtime SIP

1. Подтверждённый production-доступ к Realtime SIP именно для нужного проекта.
2. SIP endpoint/domain, способ регистрации или inbound-call acceptance, формат webhook и подпись событий.
3. Требования к TLS/SRTP, кодекам, caller ID, таймаутам и максимальной длительности.
4. Способ назначения одного и того же agent prompt/tools, которые используются в чате.
5. Разрешённый механизм server-side tools: наличие, тарифы, SPA, акции, заявка и перевод менеджеру.

### Т2

1. Номер/очередь менеджеров и рабочие часы.
2. Разрешённый способ внешнего перевода и callback результата.
3. Правила fallback: если менеджер не ответил, оставить заявку/заказать обратный звонок.
4. Требования к записи и хранению телефонных данных.

## Техническое решение после получения данных

Сначала проверяется прямой путь Mango → Realtime SIP. SBC добавляется только если не сходятся требования TLS/SRTP, кодеков, авторизации или двустороннего media stream. SBC не должен содержать бизнес-логику: он занимается сигнализацией, медиа, нормализацией кодека и проверкой webhook.

События входящего звонка должны быть идемпотентными по `providerCallId`. Для каждой сессии сохраняются только необходимые метаданные и транскрипт. Секреты не сохраняются в БД и не логируются.

Голосовой слой должен использовать тот же контекстный адаптер, что и чат: даты при новом упоминании заменяются целиком, сущности извлекаются за один ход, запрос «другие даты» сбрасывает только старый диапазон, а SPA/акции не возвращают диалог в booking-опросник. Ответы для телефона короткие, без упоминания внутренних поставщиков и технических названий.

## Критерии пилота

- Входящий звонок проходит по цепочке и создаёт одну запись `VoiceCall`.
- Агент отвечает на русском и использует опубликованные voice-знания/правила.
- Проверка наличия и предложения не выдумываются; бронирование не создаётся без подтверждённого пользовательского действия.
- Запрос менеджера переводит звонок и сохраняет результат перевода.
- При сбое SIP/AI звонок получает понятный fallback, а менеджеру создаётся заявка.
- Завершение звонка идемпотентно сохраняет итог, извлечённые данные и ссылку на запись, если провайдер её отдаёт.

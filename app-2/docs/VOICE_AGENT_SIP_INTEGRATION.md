# Голосовой агент через Mango Office

## Цепочка звонка и расписание

Планируемая схема для единого номера T2:

- в рабочее время T2 направляет звонок в очередь менеджеров;
- в нерабочее время T2 направляет звонок на текущий входящий маршрут Mango;
- Mango передаёт вызов голосовому агенту, который отвечает на вопросы и при
  согласии гостя сохраняет заявку на обратный звонок;
- менеджер видит заявку в карточке звонка и отмечает её выполненной после
  обратного звонка.

Расписание и календарь рабочих/праздничных дней задаются на стороне T2. Сам
агент не определяет рабочее время и не переключает вызов: пока маршрут T2 не
настроен и не проверен, это разделение не действует для реальных звонков.

## Backend-контур

- `POST /api/voice-agent/mango/webhook` принимает события Mango идемпотентно по
  `callId`.
- `POST /api/voice-agent/answer` формирует ответ агента по базе знаний.
- `POST /api/voice-agent/tools` выполняет консультационные инструменты и
  `request_callback`. Действие `transfer_to_manager` больше не доступно
  голосовой модели и отклоняется backend.
- `check_availability` и `compare_rooms` используют Eptera только для чтения
  наличия, подбора и сравнения вариантов. Голосовой агент не получает
  инструментов создания брони, создания платежа или передачи оплаты в Eptera.
- При согласии гостя `request_callback` сохраняет телефон, причину, имя и
  желаемое время в обращении, связанном со звонком. Повторный вызов инструмента
  для одной записи не создаёт повторную заявку. Менеджерам с разрешением на
  журнал звонков ставится push-уведомление; оно ведёт в карточку звонка и не
  содержит телефон гостя.
- Статус обратного звонка хранится в JSON-поле существующего обращения: новая
  таблица и миграция базы для этой логики не нужны. Из карточки звонка менеджер
  может отметить перезвон выполненным.
- Завершение события сохраняет транскрипцию, итог, извлечённые данные и запись,
  если Mango передал доступную HTTPS-ссылку.

## Переменные

- `MANGO_VPBX_API_KEY` и `MANGO_VPBX_API_SALT` — подпись запросов Mango.
- `VOICE_AGENT_PUBLIC_WEBHOOK_URL` — публичный URL webhook Mango.
- `AMAZI_AI_GATEWAY_OPENAI_API_KEY` и
  `AMAZI_AI_GATEWAY_OPENAI_BASE_URL` — серверный доступ голосового агента к AI.

Секреты хранятся только на backend и не выводятся в логи или frontend.

## Логика агента

Агент начинает звонок приветствием как голосовой помощник Алсмы и отвечает по-
русски, вежливо, коротко и по существу. Он консультирует об акциях, SPA,
аппаратных процедурах, мероприятиях и других темах по опубликованным знаниям.
Внутренние системы и интеграции гостю не называет.

Когда гость спрашивает про номер или хочет его забронировать, агент может
проверить наличие и сообщить подтверждённый результат. Сам он не оформляет
бронь, не создаёт платёж и не переводит звонок. Если гостю нужен менеджер или
ручное оформление, агент предлагает обратный звонок и создаёт заявку только
после явной просьбы/согласия. Если номер звонящего не передан, агент просит
номер и повторяет его для подтверждения. Об обещанном перезвоне он сообщает
только после успешного сохранения заявки.

Поиск нескольких номеров поддерживает общее число взрослых и количество
номеров, но не всегда подтверждает распределение гостей по каждому номеру.
Агент не должен утверждать, что такой конкретный состав проверен, если ответ
поиска этого не показывает; в этом случае он предлагает уточнить размещение у
менеджера. Перевод выполняется только после полного завершения озвученной
фразы и явного согласия гостя.

При подтверждённом отказе Realtime-ответа backend один раз пытается озвучить
короткое нейтральное сообщение на русском без вызова инструментов. Отменённый
ответ (например, когда гость перебил агента) не вызывает такого сообщения.
В диагностические журналы попадают код и стадия сбоя, но не текст разговора,
аудио или полный текст ошибки провайдера.

## Записи и доступ

Звонки, транскрипции и записи доступны только администраторам и менеджерам с
соответствующим административным разрешением. Срок хранения определяется
действующей политикой обработки данных; автоматическое удаление по конкретному
сроку в проекте не заявляется и не выполняется. Запись Mango может сохраниться,
даже если распознавание через AI Gateway завершилось ошибкой; повторная попытка
в карточке звонка показывает безопасный код сбоя и ID запроса, если шлюз их
вернул.

## Требование к Mango

Маршрут входящего звонка в Mango остаётся отдельной настройкой телефонии.
Существующие события Mango продолжают связывать звонок, транскрипцию и запись
по `entry_id`; для создания callback-заявки команда перевода Mango не требуется.
Реальные рабочие/нерабочие маршруты, номер Mango и сохранение исходного номера
гостя ещё нужно проверить в кабинетах T2 и Mango.

После настройки телефонии проверьте реальным звонком: звонок в рабочее время
поступает менеджерам, в нерабочее — агенту; гость может согласиться на callback,
заявка появляется в карточке звонка, менеджер получает уведомление и может
закрыть заявку. Дополнительно проверьте звонок без переданного Caller ID.
Локальные проверки: `pnpm test:voice`. Для регрессий PostgreSQL задайте
`VOICE_TEST_DATABASE_URL` на отдельную тестовую базу с применённой схемой.

Для полноценного живого разговора Mango должен передавать в webhook или
медиаканал двустороннее аудио и события речи. Один только webhook с финальной
транскрипцией позволяет сохранить звонок, обработать заявку и выполнить
перевод, но не является живым аудиодиалогом. В проекте не добавляются
неподтверждённые Mango API-методы: используются только доступные события,
официальный API перевода и переданные Mango данные записи.

## Текущий статус SIP

Для существующего прямого входящего OpenAI SIP используются
`OPENAI_SIP_API_KEY`, `OPENAI_SIP_BASE_URL` и `OPENAI_SIP_WEBHOOK_SECRET`.
OpenAI отправляет `realtime.call.incoming` на
`POST /api/voice-agent/sip/incoming`; backend проверяет подпись и принимает
звонок через Calls API с моделью `gpt-realtime`.

Диагностика доступна на `GET /api/voice-agent/sip/status`. SIP URI для Mango:
`sip:<OPENAI_PROJECT_ID>@sip.api.openai.com;transport=tls`. Обычные HTTP-запросы
и внутренний WebSocket-тест продолжают работать через Amazi AI Gateway.

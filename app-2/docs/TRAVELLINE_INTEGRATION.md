# Интеграция TravelLine

## Реализация

При `TRAVELLINE_ENABLED=true` TravelLine заменяет Eptera для поиска и новых
бронирований. Чат и голосовой агент используют Content API и Search API.
Оформление и оплата выполняются в штатном TL: Booking Engine: сайт передаёт
даты и состав гостей в настроенную форму. Выбор номера и тарифа гость
подтверждает в TravelLine. Создание брони, списание денег и отмена через
Partner API не выполняются. Старые брони Eptera сохраняются в истории.

Подключены переход из `/booking`, административная привязка брони к гостю,
Read Reservation API, серверный опрос и защищённая очередь вебхуков. Сбой API
не блокирует чтение сохранённой истории гостя. Неизвестный статус провайдера
не интерпретируется как подтверждённая или оплаченная бронь.

## Конфигурация backend

Все переменные относятся только к приложению `бек`:

| Переменная                  | Назначение                                                |
| --------------------------- | --------------------------------------------------------- |
| `TRAVELLINE_ENABLED`        | `false` до проверки модуля; `true` переключает провайдера |
| `TRAVELLINE_CLIENT_ID`      | Идентификатор API-подключения                             |
| `TRAVELLINE_CLIENT_SECRET`  | Секрет подключения                                        |
| `TRAVELLINE_PROPERTY_ID`    | `21062`                                                   |
| `TRAVELLINE_BOOKING_URL`    | Проверенный HTTPS-адрес страницы с модулем TravelLine     |
| `TRAVELLINE_WEBHOOK_SECRET` | Необязательно: случайный секрет от 32 символов            |

Секреты не помещаются во frontend, Git или ссылки. Серверный OAuth использует
`https://partner.tlintegration.com/auth/token`, кеширует и обновляет токен.
Запросы ограничены таймаутами, тела ошибок провайдера не выдаются гостю и
не записываются в журнал.

До запуска новой версии применить аддитивную миграцию
`20261124090000_travelline_booking_provider` штатным механизмом backend.
Она добавляет источник, внешние идентификаторы и времена синхронизации,
уникальность объекта/номера. Существующие данные не пересоздаются.

## Маршруты

- `GET /api/travelline/config`: публичная готовность без ключей.
- `GET /api/travelline/offers`: даты, взрослые, возраста детей; один номер.
- `GET /api/travelline/checkout`: валидация и HTTP 302 в модуль.
- `GET /api/admin/travelline/status`: право `integrations.access`.
- `POST /api/admin/travelline/link-booking`: административная сессия,
  право `dashboard.access`, `userId`, `bookingNumber`, `ownershipConfirmed: true`.
- `POST /api/travelline/cancellation-requests`: сессия гостя,
  `bookingId`, необязательный `reason`.
- `POST /api/travelline/webhook`: секрет в заголовке `API-KEY`.

Несколько номеров предлагается выбирать в форме TravelLine. Search API не
используется для выдуманного распределения гостей. Предзаполнение модуля:
`date`, `nights`, `adults`, `children`, `children-age`. Номер/тариф из
консультации не считается гарантированно переданным.

## Инструкция сотруднику

1. Гость оформляет бронь в TravelLine и входит в личный кабинет ALSMA.
2. Сотрудник проверяет в TravelLine принадлежность брони гостю. В проверенном
   ответе API отеля нет телефона и email; автоматическое сопоставление по
   имени или одному номеру брони не применяется.
3. В админке ALSMA открыть карточку клиента, указать номер брони TravelLine,
   подтвердить проверку владельца и привязать. Переназначение брони другого
   клиента запрещено.
4. Статусы обновляются автоматически. Фоновый проход раз в минуту обрабатывает
   до 10 событий и 10 броней старше 10 минут. При входе гостя проверяются до
   10 броней старше 5 минут. Ошибки повторяются; интервалы не являются SLA.
5. Запрос гостя на отмену создаёт заявку сотруднику. Отменить бронь нужно
   вручную в шахматке TravelLine с проверкой условий и возврата. До
   подтверждения Read Reservation API бронь не показывается отменённой.
   Автоматического возврата денег нет.

Вебхуки необязательны: опрос работает без них. Для ускорения после развёртывания
зарегистрировать реализованный HTTPS endpoint и тот же `API-KEY` в TravelLine.
События сохраняются в БД до ответа 204. Дубликаты не сбрасывают обработку,
неизвестные брони не создают гостей и не привязываются автоматически.
Обработанные события очищаются через 30 дней.

## Ограничения запуска

- Кабинет предупреждает о недоступности продаж на ближайшие шесть месяцев.
  Проверенный тариф «Все включено!» неактивен, доступность заблокирована.
  Отелю необходимо проверить тарифы, ограничения и доступность.
- «Получить ссылку на тариф» выдаёт шаблон
  `http://www.site.com?be-offer=1002523`, а не действующий модуль. На
  существующем публичном сайте обнаружен UHotels. Нужны установка TravelLine
  на целевую страницу и её проверенный HTTPS-адрес для `TRAVELLINE_BOOKING_URL`.
- Нужны развёртывание кода и миграции, проверка привязки на БД и согласованное
  контрольное бронирование в модуле. Локальные тесты не подтверждают оплату
  или применение миграции в production.

Не включать флаг ради исчезновения предупреждения: это отключает Eptera,
а без модуля checkout намеренно отвечает 503. После настройки проверить поиск,
переход с детьми, привязанную бронь, обновление статуса и заявку на отмену.
Старые брони не пересоздавать.

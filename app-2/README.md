## PDF-документы сайта

Медиа-эндпоинт управления сайтом принимает PDF-файлы, которые используются коллекциями документов публичных страниц.

При загрузке PDF backend рендерит первую страницу целиком в JPEG через PDF-рендерер: в превью попадают текст, векторные элементы, фоновые изображения и другие объекты страницы. Встроенные изображения PDF больше не извлекаются напрямую, поэтому фоновая картинка не может подменить страницу. Основной PDF и JPEG-превью хранятся в managed storage отдельно; если рендеринг конкретного PDF не удался, основной файл всё равно сохраняется, но `previewUrl` не возвращается.

Публичный `GET /api/media/managed/:objectToken` проксирует содержимое файла через backend вместо редиректа на внешний storage-домен и отключает COOP-блокировку для этого media-ответа. Это позволяет браузерам открыть PDF и превью без перехода на внешний домен.

## AI-агент и Amazi AI Gateway

Сообщения из `POST /api/chat/messages` асинхронно передаются AI-агенту. Он сам формулирует ответы на основе истории диалога, опубликованной базы знаний и проверенных результатов доступных инструментов. Приложение не подменяет обычные ответы готовыми сценариями: оно выполняет выбранное агентом действие, валидирует обязательные данные и возвращает агенту подтверждённый результат для ответа гостю. При недоступности AI показывается только краткое техническое сообщение об ошибке, а не посторонний ответ из базы знаний.

Для проживания агент использует актуальные предложения Eptera; backend выполняет поиск доступности и создание брони. Перед созданием брони обязательно проверяется явное подтверждение гостя, выбранный вариант и обязательные данные. После успешного создания ссылка оплаты прикладывается к сообщению, а AI формулирует гостю подтверждение по фактическому результату. Агент также может выбрать действие регистрации обращения или перевода сотруднику; сведения сохраняются только после вызова соответствующего действия.

Перед созданием брони агент запрашивает недостающие контакты и не подставляет email, сгенерированный моделью. Сохранённый телефон из первого обращения используется повторно. Email, явно сообщённый гостем, сохраняется у гостя и брони, передаётся ЮKassa для чека и используется для сопоставления брони с профилем: после входа по коду на эту почту гость видит бронь в личном кабинете.

OpenAI-совместимый запрос отправляется только с backend на `/chat/completions` через `AMAZI_AI_GATEWAY_OPENAI_API_KEY` и `AMAZI_AI_GATEWAY_OPENAI_BASE_URL`. Если провайдер не поддерживает `response_format`, backend повторяет запрос без него и разбирает обычный или fenced JSON-ответ. Ключи не передаются во frontend.

## Browser CORS и preflight

Backend обрабатывает `OPTIONS` до API-маршрутов и возвращает `204` с разрешёнными методами `GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS`, заголовками `Authorization, Content-Type` и кэшированием preflight на 10 минут. Если preview backend недоступен, внешний gateway может показать `502 Project preview is unavailable`; такой ответ не является ошибкой CORS и требует восстановления runtime-приложения.

## Запуск backend

При ошибке конфигурации, подключения к базе или миграции backend завершает запуск с безопасным сообщением причины без вывода значений переменных окружения. После исправления runtime-переменных приложение нужно пересобрать или перезапустить, чтобы preview endpoint снова стал доступен.

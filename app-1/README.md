## Бронирование и оплата

После заполнения контактов пользователь выбирает способ оплаты: полная стоимость проживания или предоплата первых суток. Сначала backend создаёт бронь в Eptera, затем создаёт платёж в ЮKassa; браузер перенаправляется на защищённую страницу ЮKassa.

## AI-чат

Виджет чата отправляет сообщения через backend, получает ответы по SSE и через резервный polling, а во время ожидания показывает состояние «Печатает…». Источник SSE строится через настроенный backend API URL, поэтому виджет работает и на preview-, и на production-домене frontend. Ответы агента и ручные ответы менеджера отображаются в одной ветке обращения. При открытии нового диалога виджет показывает одно статичное приветствие «Здравствуйте! Я ИИ-помощник АЛСМА»; это приветствие не добавляется к последующим ответам агента. Если агент собрал и подтвердил параметры поездки и Eptera вернул доступные варианты, сообщение также содержит кнопку «Открыть бронирование» со ссылкой, в которой заранее заполнены даты, гости и количество номеров.

## Настройки AI-агента

Раздел администратора «Сценарии агентов» содержит вкладки для сценариев ответов и правил передачи диалога, а также настройки самого агента:

- «Общие настройки» — Eptera Booking API как источник актуальных данных, тон общения, приветствие и ссылка на инструмент бронирования;
- «Возможности агента» — проверка наличия, создание обращения и передача сотруднику. Создание брони агентом явно запрещено;
- «Данные клиента» — имя, телефон, количество гостей и даты заезда/выезда, которые можно собрать в обращении;
- «Уведомления» — обязательная прозрачная маркировка ответа AI и текст уведомления для клиента.

История диалогов продолжает храниться в обращениях по отдельным веткам. Срок хранения и дополнительные правила обработки персональных данных пока не фиксируются в интерфейсе.

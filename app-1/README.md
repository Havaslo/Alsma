## Бронирование и оплата

После заполнения контактов пользователь выбирает способ оплаты: полная стоимость проживания или предоплата первых суток. Сначала backend создаёт бронь в Eptera, затем создаёт платёж в ЮKassa; браузер перенаправляется на защищённую страницу ЮKassa.

## AI-чат

Виджет чата отправляет сообщения через backend, получает ответы по SSE и через резервный polling, а во время ожидания показывает состояние «Печатает…». Источник SSE строится через настроенный backend API URL, поэтому виджет работает и на preview-, и на production-домене frontend. Ответы агента и ручные ответы менеджера отображаются в одной ветке обращения. В шапке виджета показывается, кто отвечает сейчас: AI-ассистент или менеджер; после передачи менеджеру AI не отвечает, пока ветку не вернут в режим агента из админки. Во время обработки ответа отображается realtime-индикатор с этапами «Анализирую ваш запрос», «Проверяю наличие в Eptera» и «Формирую ответ». Эти события приходят по SSE и исчезают только после финального сообщения или ошибки. При открытии нового диалога виджет показывает одно статичное приветствие «Здравствуйте! Я ИИ-помощник АЛСМА»; это приветствие не добавляется к последующим ответам агента. Если агент собрал и подтвердил параметры поездки и Eptera вернул доступные варианты, сообщение также содержит кнопку «Открыть бронирование» со ссылкой, в которой заранее заполнены даты, гости и количество номеров.

## Настройки AI-агента

Раздел администратора «Сценарии агентов» содержит вкладки для сценариев ответов и правил передачи диалога, а также настройки самого агента. Сценарии, правила и настройки загружаются и сохраняются через backend; после обновления страницы значения берутся из базы данных:

- «Общие настройки» — Eptera Booking API как источник актуальных данных, тон общения, приветствие и ссылка на инструмент бронирования;
- «Возможности агента» — проверка наличия, создание обращения и передача сотруднику. Создание брони агентом явно запрещено;
- «Данные клиента» — имя, телефон, количество гостей и даты заезда/выезда, которые можно собрать в обращении;
- «Уведомления» — обязательная прозрачная маркировка ответа AI и текст уведомления для клиента.

История диалогов продолжает храниться в обращениях по отдельным веткам. Срок хранения и дополнительные правила обработки персональных данных пока не фиксируются в интерфейсе.

## Контент главной страницы

Изображение блока «Корпоративные заезды» на главной странице подключается в `src/components/site/HomeDiscoverySections.tsx` отдельным локальным ассетом `src/assets/alsma/corporate-checkins.jpg`. Оно не зависит от карточек сценариев отдыха и их данных в админке.

## Галерея страницы торжеств

Карточка «Выездная регистрация на природе» на странице `/celebrations` использует локальный ассет `src/assets/alsma/event-outdoor-ceremony.jpg` через коллекцию `EVENT_GALLERY`.

В шапке админ-панели есть центр уведомлений: он получает последние заявки сайта, обращения и заявки на бронирование через backend, показывает непрочитанный счётчик, даёт переход к соответствующему разделу и подаёт звуковой сигнал при новых событиях. Проверка выполняется каждые 10 секунд; браузер может потребовать первое взаимодействие пользователя для разрешения звука.
На странице «Заявки сайта» отображаются только заявки из форм обратной связи. Чаты и обращения находятся в разделе «Обращения», где ветки сортируются по `AdminRequest.updatedAt`, показывают время последней активности и получают метку «Новое сообщение» до открытия ветки.
В разделе «Обращения» колонка «Кто отвечает» показывает текущего ответственного: AI-агент, менеджер или «Запрошен менеджер». Последний статус устанавливается при передаче диалога агентом и снимается после ручного вмешательства менеджера или возврата ветки агенту.

## Сценарии AI-агента

Агент ведёт консультацию по этапам: определяет формат отдыха, предлагает выбор между проживанием, SPA на один день и процедурами, собирает только недостающие параметры для бронирования и не повторяет уже данное описание. Для SPA и аппаратных процедур он может вернуть отдельную кнопку перехода на соответствующую страницу; для проживания кнопка появляется только после проверки параметров через Eptera. Базовые сценарии и правила передачи менеджеру создаются backend при первом обращении, если записи с такими названиями ещё отсутствуют.

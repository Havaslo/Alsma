# Фабрика контента

## Назначение и рабочий процесс

Фабрика контента — отдельное рабочее пространство SMM-специалиста: задача → варианты исходного материала → визуал → версии по каналам → проверка → согласование → публикация или планирование. AI-подсказки поддерживают работу сотрудника, но не заменяют его решение. Материал не должен публиковаться до явного согласования пользователем.

Основные области интерфейса: создание, контент-план, медиатека и история с сохранёнными черновиками. Для одной публикации поддерживаются каналы VK, Telegram, Max, Instagram и Яндекс.Дзен; у каждого канала собственные текст и предпросмотр.

## Доступ и границы страницы

Маршрут интерфейса: `/admin/content-factory`. Он проверяет вход администратора и разрешения `site.access` или `site.manage` (либо `*`). Страница намеренно не использует общий `AdminShell`: она показывает только содержимое Фабрики контента, без административной шапки, меню и подвала.

## Хранение черновиков и изображений

- Кнопка «Сохранить черновик» сохраняет заголовок, задачу, выбранные каналы и варианты текста/изображений в `content_factory_drafts`. Список открывается на вкладке «История и черновики»; повторное сохранение открытого материала обновляет ту же запись.
- Черновики видны всем администраторам с `site.access` или `site.manage`, а не только создавшему их сотруднику. При удалении учётной записи автора черновик сохраняется, а ссылка на автора становится пустой.
- В медиатеку можно загружать JPG, PNG, WebP и GIF до 50 МБ. Файлы сохраняются в управляемом объектном хранилище, а метаданные и непрозрачный идентификатор объекта — в `content_factory_media`; браузер не получает токен хранилища.
- Разработка и production используют общую базу и пространство объектного хранилища проекта. Поэтому сохранённые черновики и загруженные изображения доступны в обоих окружениях. Удаление медиа из интерфейса не предусмотрено; объекты хранятся без срока автоматического удаления.

## AI-генерация и тестовый режим

Фабрика контента использует подключённый Amazi AI Gateway только на сервере. Текстовые варианты создаёт `gpt-4.1-mini`, изображения редактирует `gpt-image-1.5` с качеством `medium`. Текстовый запрос включает текст задачи, выбранные каналы и пиксели текущей исходной фотографии; запрос изображения передаёт сам выбранный фотофайл в режиме редактирования, а не только описание словами. Секреты Gateway не передаются в браузер. AI просит использовать видимые детали фото как контекст, не выдумывать факты об услугах, ценах и сроках и создавать только один кадр для заданного канала. Результат изображения обрезается под профиль этого канала, сохраняется PNG в объектном хранилище и регистрируется в медиатеке; выбранная версия черновика автоматически обновляется ссылкой на новый кадр. Модель может менять детали фотографии, поэтому факты и визуальный результат всё равно нужно проверить человеку.

Единый справочник профилей каналов попадает и в промты, и в подсказки интерфейса. Он задаёт голос/структуру текста, формат файла, рекомендованное соотношение сторон и размер выходного кадра:

| Канал       | Правило текста                                                               | Формат изображения для тестового кадра                                                                 | Множественные изображения                                                                                                                        |
| ----------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| VK          | Короткая понятная первая строка, проверенные факты, один естественный призыв | JPEG/PNG, 4:5, 1080×1350 — редакционная рекомендация, не заявленный обязательный лимит VK              | API поддерживает несколько вложений в записи; интерфейс VK может отображать их по-разному, это не обещанная универсальная карусель               |
| Telegram    | Живой компактный текст, удобные переносы, минимум хэштегов                   | JPEG/PNG, 1:1, 1200×1200 — рекомендация для альбома                                                    | Bot API `sendMediaGroup` требует 2–10 элементов в альбоме                                                                                        |
| MAX         | Самостоятельное короткое сообщение с ясной первой строкой                    | JPG/JPEG/PNG, 1:1, 1200×1200 — рекомендация; API ограничивает один файл до 50 МБ и 7680×7680 px        | В одном сообщении API поддерживает до 12 медиа-вложений; это группа вложений, а не эквивалент Instagram-карусели                                 |
| Instagram   | Короткая подпись с зацепкой, переносами и несколькими точными хэштегами      | JPEG, 4:5, 1080×1350 — профиль ленты                                                                   | Карусель — 2–10 изображений/видео; API обрезает элементы по соотношению сторон первого кадра. В текущем интерфейсе создаётся один кадр за запрос |
| Яндекс.Дзен | Статья с полезным контекстом и подзаголовками, не короткая подпись           | JPEG/PNG, 16:9, 1600×900 — наша редакционная рекомендация; не подтверждённый универсальный лимит Дзена | Можно подготовить последовательность иллюстраций для статьи; профиль не заявляет лимит свайп-карусели                                            |

Соотношения сторон и пиксельные размеры в этой таблице — внутренние рекомендации для согласованного предпросмотра, кроме отдельно обозначенных API ограничений. Они не означают, что площадки принимают только этот размер. Источники: [Telegram Bot API](https://core.telegram.org/bots/api), [справка MAX о нескольких медиафайлах](https://dev.max.ru/docs-api/use-cases/sending-messages/media), [лимиты изображений MAX](https://dev.max.ru/docs-api/use-cases/sending-messages/attachment-types), [Instagram API от Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-db99ce99-bf76-475c-8b76-718576c11cae), [схема VK API](https://github.com/VKCOM/vk-api-schema/blob/master/wall/objects.json).

Сгенерированный текст автоматически сохраняется как черновик и доступен во вкладке истории. Изображение автоматически сохраняется как материал медиатеки. Ошибка сохранения текста не удаляет уже показанные варианты и сопровождается просьбой сохранить их вручную. AI-генерация не обращается к подключённым социальным каналам.

Публикация в тестовом режиме отключена: интерфейс не предлагает отправить согласованный материал. Добавление даты доступно только для демонстрационного контент-плана и ничего не отправляет. История показывает реальные сохранённые черновики, а не фиктивные показатели публикаций. Контент-план и аналитика пока демонстрационные.

Фотографии по умолчанию используют существующие локальные материалы ALSMA. Пример акции использует скидку 20% из демонстрационной задачи; период 1–30 ноября 2026 года — пример, а не подтверждённое условие реальной акции.

## Необходимое для промышленного запуска

- Определить доверенный источник фактов об услугах, акциях, сроках и условиях; перед публикацией проверять неизвестные условия, не придумывать их.
- Подключить и авторизовать каналы публикации с проверкой возможностей и ограничений каждой площадки.
- Хранить версии материала, выбранный визуал, состояние согласования, автора и время подтверждения, расписание и результат отправки.
- Планировать по каналам отдельно и показывать фактические статусы публикации и ошибки доставки.
- Получать метрики только из подключённых каналов и помечать источник и период измерения.
